## 1. ITS research: model tracing, constraint-based tutors, Andes, Lynnette. How they represent solution paths and buggy rules

### Takeaway
There are three main ways to represent the solution space. (1) Model tracing (Cognitive Tutor, CTAT rule-based tutors, Lynnette) runs a production system of correct rules plus buggy rules alongside the student and matches each student step against the rule firings. (2) Constraint-based tutors (SQL-Tutor and others) encode only correct-state constraints of the form (relevance, satisfaction), with no paths and no mal-rules. (3) Andes (physics) precomputes a solution graph of all acceptable solutions and looks up each student entry in it. For an equation solver the model-tracing / solution-graph style fits best, because steps are rewrites. Constraints are a cheap complement for "is this state well-formed / closer to solved".

### Cited Findings
- A Cognitive Tutor's cognitive model is a production system that covers the multiple strategies students might use as well as their typical misconceptions. Model tracing follows the student's chosen path so that hints and feedback are tied to the step taken. — [ScienceDirect topic overview: Cognitive Tutor](https://www.sciencedirect.com/topics/computer-science/cognitive-tutor)
- A model-tracing tutor "typically provides a set of buggy rules that model incorrect reasoning. If a trace contains one or several buggy rules, the step is assumed to be incorrect and error specific feedback can be given." — [Towards an Intelligent Tutor for Mathematical Proofs (arXiv 1202.4828)](https://arxiv.org/pdf/1202.4828)
- Search order for buggy rules: one patented design first runs the model-tracing algorithm with no buggy productions, and on failure reruns it with one buggy production, then more, so the interpretation uses as few buggy rules as possible. — [US Patent 6634887, tutoring with interactive dialog](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/6634887)
- Anderson's algebra tutor had rules modeling an ideal student's knowledge (e.g., distribution). Its buggy rules were developed by observing student errors and coding the inferred buggy productions one at a time. — [Anderson, Cognitive Modelling and Intelligent Tutoring (DTIC ADA165981)](https://apps.dtic.mil/sti/tr/pdf/ADA165981.pdf) (snippet fragmentary)
- Knowledge tracing is a separate layer. It tracks gradual acquisition of each production rule across problems. Bayesian Knowledge Tracing uses 4 parameters per knowledge component in an HMM. — [Deep Knowledge Tracing with Learning Curves (arXiv 2008.01169)](https://arxiv.org/pdf/2008.01169); [ScienceDirect overview](https://www.sciencedirect.com/topics/computer-science/cognitive-tutor)
- Lynnette (equation solving, grades 6–8) was first an example-tracing tutor (behavior graphs authored by demonstration in CTAT). It was re-implemented in 2014 as a rule-based Cognitive Tutor in CTAT "so as to be more flexible in recognizing students' major and minor solution variations", even though the example-tracing version had proven effective in multiple classroom studies. — [Aleven et al., Example-Tracing Tutors, IJAIED 2016](https://www.cs.cmu.edu/~bmclaren/pubs/AlevenEtAl-CTAT-IJAIED2016.pdf); [Springer version](https://link.springer.com/article/10.1007/s40593-015-0088-2)
- Lynnette is still used as an open-source research tutor in 2025–2026 work, described as supporting algebraic equation solving "through step-by-step interaction". — [arXiv 2605.08943](https://arxiv.org/pdf/2605.08943); see also [CTAT+TutorShop platform paper (arXiv 2502.10395)](https://arxiv.org/pdf/2502.10395) and [Can LLMs match tutoring system... (arXiv 2504.05570)](https://arxiv.org/pdf/2504.05570)
- Constraint-based modeling (Ohlsson; Mitrovic's group) "uses abstraction to avoid the need to model students' misconceptions. Constraints represent only correct knowledge." Each constraint has a relevance condition Cr (the class of states where it applies) and a satisfaction condition (the subset where it holds). A relevant but unsatisfied constraint is "violated" and triggers remediation. Evaluation runs in two passes: match all relevance patterns, then test satisfaction for the relevant ones. — [Mitrovic, Koedinger & Martin 2003 comparison](https://www.public.asu.edu/~kvanlehn/ITScourse2009/Readings/Mitrovic%20Koedinger%20Martin%202003.pdf); [Mitrovic 2006](https://www.public.asu.edu/~kvanlehn/ITScourse2009/Readings/Mitrovic%202006.pdf); [summary of Mitrovic & Ohlsson 99](https://nats-www.informatik.uni-hamburg.de/bin/view/User/SummaryForMitrovicOhlsson99)
- Andes builds its Bayesian networks automatically from the output of a problem solver that generates *all* acceptable solutions (a solution graph). The Action Interpreter looks each student entry up in that graph for immediate correct/incorrect feedback. — [Procedural help in Andes (Gertner, Conati, VanLehn)](https://www.cse.unr.edu/~sjose/Papers%20Referenced/Procedural%20help%20in%20Andes%20Generating%20hints%20using%20a%20Bayesian%20network%20student%20model.pdf)
- Andes on-demand help has two modes. "What's wrong" gives hints about an incorrect step. "Next step" delivers goal scaffolding as a sequence of increasingly specific hints. — [VanLehn et al. 2005, Andes lessons learned, IJAIED 15(3)](https://www.public.asu.edu/~kvanlehn/distrib/AndesLessonsLearnedForWeb.pdf); [2015 commentary, IJAIED](https://link.springer.com/article/10.1007/s40593-015-0067-7)
- Andes limits: to stay tractable, it advised only on physics rules. Students rarely typed the primitive equations generated directly by rule applications; they combined steps. In one comparison Andes agreed with instructors on only 3 of 21 snapshots where instructors agreed among themselves. — [VanLehn et al. 2005](https://www.public.asu.edu/~kvanlehn/distrib/AndesLessonsLearnedForWeb.pdf); [2015 commentary](https://link.springer.com/article/10.1007/s40593-015-0067-7)
- VanLehn's "behavior of tutoring systems" paper frames step-based tutors as an outer loop (task selection) and an inner loop (step feedback, hints). — [VanLehn 2006, IJAIED](https://www.cs.uky.edu/~sgware/reading/papers/vanlehn2006behavior.pdf)

### Inferences
- For `@math-blocks/solver`: represent each rewrite as a rule with an id (a knowledge component), pre-condition, transform and message template. Model "mal-rules" as the same type with a `buggy: true` flag and a misconception message. Search correct rules first and add buggy rules only when no correct explanation exists (the patent's minimal-buggy-rules ordering).
- Andes' lesson that students skip and combine primitive steps implies the step checker must accept multi-rule jumps, not just single rule applications (see Section 2, "combined steps").
- Lynnette's move from example-tracing (fixed graphs) to rule-based tracing argues for generating the solution space dynamically from rules rather than authoring per-problem paths. That is what a rewriting core does naturally.
- **[unverified]** ASSISTments is mainly a problem/hint-sequence platform (scaffolding questions and authored hints, answer-level checking) rather than a step-level rewriting tutor. Little in it informs a rewriting core beyond the hint-ladder UX. I found no source this session.

## 2. Step checking and rule recognition, including the Ideas framework (Heeren, Jeuring, Gerdes) in depth

### Takeaway
The Ideas framework (Open Universiteit / Utrecht, about 2008–present) is the closest existing design to what math-blocks needs. A domain gives (a) rewrite rules, including buggy rules, (b) a strategy, written in a combinator language, that describes the allowed sequences of rule applications, and (c) equivalence and similarity relations ("views" / normal forms). Feedback services (`allfirsts`, `onefirst`, `derivation`, `diagnose`, …) are all derived from the strategy and rules by treating "is the student's sequence of steps a prefix of the strategy's language?" as a parsing problem. Step diagnosis returns a classification such as Expected / Detour / Similar / Buggy / NotEquivalent / Correct. Combined steps (several rules at once) are a known hard case; 2025 work diagnoses them by evaluating final answers.

### Cited Findings — Ideas framework
- "Specifying Rewrite Strategies for Interactive Exercises", Heeren, Jeuring & Gerdes, *Mathematics in Computer Science* 3:349–370 (2010). It presents a strategy language for specifying how to solve an exercise, used to generate feedback automatically, including when a user makes an erroneous step. Example domains: logic to DNF, matrix reduction, fractions. — [Paper page (cs.ou.nl)](https://cs.ou.nl/members/bastiaan/SpecifyingStrategiesJournal.html); [PDF](https://cs.ou.nl/members/bastiaan/StrategiesForExercisesJournal.pdf)
- Tracking a learner's intermediate steps against a strategy is treated as a **parsing problem**. A strategy describes a language of valid rewrite-rule sequences, and techniques from parsing context-free languages are reused. — [Specifying Strategies (search summary)](https://cs.ou.nl/members/bastiaan/StrategiesForExercisesJournal.pdf); [Utrecht tech report CS-2010-028](https://ics-archive.science.uu.nl/research/techreps/repo/CS-2010/2010-028.pdf)
- A 2011 follow-up (Heeren & Jeuring) adds **interleaving** of strategies, which the authors argue many exercises need. — [Interleaving Strategies](https://cs.ou.nl/members/bastiaan/InterleavingStrategies.html); [TR CS-2011-016](https://ics-archive.science.uu.nl/research/techreps/repo/CS-2011/2011-016.pdf)
- Feedback services defined in "Properties of Exercise Strategies" (Heeren & Jeuring, 2010):
  - `allfirsts`: "returns all next steps that are allowed by a strategy in a particular state".
  - `onefirst`: returns a single next step; it "uses the allfirsts service and the rule ordering".
  - `derivation`: "returns a worked-out solution of an exercise starting with the current expression".
  - `diagnose`: classifies a submitted expression. Classes include **Expected** (the strategy anticipated the step) and **Detour** (the step departs from the strategy but the applied rule is recognized). Related versions also list **NotEq** (not equivalent) and **Buggy** (matches a known misconception rule).
  — [Properties of Exercise Strategies (arXiv 1012.5561)](https://arxiv.org/pdf/1012.5561); [ResearchGate copy](https://www.researchgate.net/publication/220485179_Properties_of_Exercise_Strategies)
- Buggy rules in Ideas encode common mistakes, e.g. a buggy distribution rule for 5(x+3) → 5x+3, and "enable specialized feedback messages when detected". — [Heeren et al., Automated Feedback for Mathematical Learning Environments, ICTMT 14 (Essen, 2019)](https://duepublico2.uni-due.de/servlets/MCRFileNodeServlet/duepublico_derivate_00071103/Heeren_et_al_Automated_feedback_mathematical_learning.pdf)
- Van der Bent, Jeuring & Heeren, "The Diagnosing Behaviour of Intelligent Tutoring Systems", describes edge cases a diagnoser must handle: inputs that are semantically equivalent yet follow a buggy rule, and inputs that a strategy expects even though they are not semantically equivalent. It also notes that diagnosing misconceptions via buggy rules can need impractically many rules even in simple domains like fractions. — [Paper PDF](https://webspace.science.uu.nl/~jeuri101/homepage/Publications/DiagnosingBehaviour.pdf) (search summary)
- **Combined steps** (2025): van der Hoek, Jeuring & Bos note that when students merge several steps the number of possible paths explodes combinatorially. They diagnose buggy rules through **final-answer evaluation**: apply candidate (buggy) rule paths, compare with the student's answer, and avoid enumerating all intermediate paths. Final-answer evaluation diagnosed 29.4% of such steps, and on a subset (n=115) the generated diagnoses matched teacher diagnoses in 97% of cases. — [arXiv 2507.13651](https://arxiv.org/abs/2507.13651); [Springer AIED 2025 chapter](https://link.springer.com/chapter/10.1007/978-3-031-98420-4_25)
- The Ideas project is a joint Open Universiteit / Utrecht effort supporting interactive learning environments. — [Utrecht University: The Ideas project](https://www.uu.nl/en/research/software-systems/software-technology-for-learning-and-teaching/research-themes/the-ideas-project); Jeuring CEFP lecture slides: [slides1.pdf](https://webspace.science.uu.nl/~jeuri101/homepage/Publications/CEFP/slides1.pdf)

### Cited Findings — lightweight checking
- A small open-source step checker (algebra-step-checker) parses each student line with math.js and compares it to the previous line **numerically** (random evaluation) to find the first wrong step, then gives Socratic hints. — [GitHub: dguywhoknows/algebra-step-checker](https://github.com/dguywhoknows/algebra-step-checker)
- MATH-VF (2025) verifies each step of LLM reasoning with a Formalizer plus a Critic that calls Z3 and SymPy. — [Step-Wise Formal Verification for LLM-Based Mathematical Problem Solving (arXiv 2505.20869)](https://arxiv.org/html/2505.20869v1)

### Inferences (design for TS)
- **[unverified, from prior knowledge of Ideas papers and the Haskell `ideas` package]** The strategy combinators are roughly: rule (atomic step), `<*>` sequence, `<|>` choice, `>|>` / `|>` left-biased choice (preference), `succeed`/`fail`, `many`/`repeat`/`option`, `label l s` (named sub-strategy, which becomes a hint level and a "substep" group), `<%>` interleave, `atomic`, `fix` for recursion, and traversals (`somewhere`, `oncetd`, `oncebu`) to apply rules at subterms. Exercises also define `equivalence` (semantic, e.g. via normal form/evaluation), `similarity` (syntactic modulo AC, used for "Similar" = same up to trivial differences), `ready` (is it solved?), and **views** (bidirectional match/build to a canonical form, e.g. a polynomial view, used for both equivalence and pattern matching). The full diagnose result set in later versions is roughly: Buggy, NotEquivalent, Similar, Expected, WrongRule, Detour, Correct, Unknown. Ideas services are exposed over JSON/XML and used by external front-ends such as the Freudenthal Institute's Digital Mathematics Environment.
- Direct mapping to `@math-blocks/solver`:
  - `Rule<T> = { id, kind: 'normal'|'buggy'|'minor', message, apply(node): node[] }`. Returning a list supports non-determinism.
  - `Strategy` = an AST of combinators (Seq, Choice, PreferLeft, Many, Label, Interleave, Somewhere). Interpreting it lazily as a stream of (rule, location, result) gives `allfirsts`. `onefirst` = the first element under rule ordering. `derivation` = iterate `onefirst` until `ready`.
  - Today's `Step{message, before, after, substeps}` tree falls out of `Label` nodes: each label becomes a parent step and the rules inside it become substeps. Granularity control is then "collapse all labels below depth d" or "collapse labels tagged arithmetic".
  - `diagnose(prevState, studentExpr)`: (1) not equivalent to prev → try buggy rules (one, then compositions) → Buggy(rule) or NotEquivalent. (2) Equivalent and similar to prev → Similar. (3) Search `allfirsts` (and k-step compositions, bounded) for a result similar to studentExpr. A match inside the strategy is Expected; a match by a known rule outside the strategy is Detour; equivalent with no matching rule is Correct/Unknown, and the strategy is restarted from the student's expression.
  - Equivalence checking: canonical-form comparison (polynomial normal form for linear/quadratic work) as the primary method. Random numeric evaluation at several points (with exact rational arithmetic, avoiding singularities) is a cheap fallback. For equations, compare solution sets or check that the equations are scalar multiples after moving everything to one side.
- The 2025 final-answer-evaluation result suggests that for multi-step jumps it is enough to search for which (buggy) rule path explains the student's answer, rather than enumerating every intermediate.

## 3. Commercial and open-source step solvers (Photomath, Microsoft Math Solver, Symbolab, MathPapa, Wolfram, mathsteps, GeoGebra, CortexJS)

### Takeaway
Little architecture is publicly documented. Wolfram|Alpha states that its steps do **not** trace the CAS's internal algorithms; they come from separate human-mimicking heuristics built on Mathematica pattern matching, reviewed by PhDs for didacticism. Socratic's open-source mathsteps (JS, archived August 2024) is the most concrete reference: it is a rule-based simplifier that emits `{oldNode, newNode, changeType, substeps}`, very close to math-blocks' Step type. Photomath and Microsoft Math Solver have no primary engineering write-ups. Microsoft Math Solver was reportedly retired in July 2025.

### Cited Findings
- Wolfram|Alpha step-by-step: the developers chose not to trace the computation algorithms. Instead they use heuristics that follow "the approach a human would most likely take" (e.g., Gaussian elimination, l'Hôpital's rule, Bernoulli's algorithm for rational integration), built on Mathematica pattern matching into a platform that "breaks down and structures solutions" like human problem solving. A team of PhD reviewers critiques solutions for accuracy, readability and didacticism. — [Wolfram|Alpha Blog, Step-by-Step Math (2009)](https://blog.wolframalpha.com/2009/12/01/step-by-step-math/); [Expanded step-by-step (2012)](https://blog.wolframalpha.com/2012/09/26/introducing-expanded-step-by-step-math-solutions/); [A New Level of Step-by-Step Solutions (2017)](https://blog.wolfram.com/2017/09/07/a-new-level-of-step-by-step-solutions-in-wolframalpha/)
- The Wolfram|Alpha 2.0 iOS app (2019) shows steps one at a time, which works as a hint ladder over the same step list. — [Wolfram Blog 2019](https://blog.wolfram.com/2019/07/17/enhanced-step-by-step-solutions-now-on-mobile-announcing-wolframalpha-2-0-for-ios/)
- mathsteps (Socratic): `simplifyExpression(str)` returns an array of steps, each with `oldNode`, `newNode`, `changeType` (e.g. `ADD_POLYNOMIAL_TERMS`) and `substeps`. `solveEquation` returns steps with old/new equation and change types such as `SIMPLIFY_LEFT_SIDE`. All labels are exported as `mathsteps.ChangeTypes`. The repo was archived (read-only) on 2024-08-29 with 2.2k stars, 61 open issues and 18 open PRs. — [GitHub socraticorg/mathsteps](https://github.com/socraticorg/mathsteps); TS port: [elu00/mathsteps-ts](https://github.com/elu00/mathsteps-ts)
- Microsoft Math Solver was reported retired on 7 July 2025, with math.microsoft.com pointing to Math Assistant in OneNote and Math Progress in Teams. This comes from a third-party site, not confirmed by Microsoft. — [mathsolver-ai.com](https://mathsolver-ai.com/microsoft-math-solver/); original launch announcement: [Microsoft Stories India](https://news.microsoft.com/en-in/microsoft-math-solver-ai-app/)
- Photomath: no primary architecture source was found. A non-primary blog claims a cloud neural network recognizes the problem and picks a method, with a separate solving engine generating the working. Treat this as unverified. — [mathsolver.cloud blog](https://mathsolver.cloud/blog/photomath/)

### Inferences
- **[unverified, from prior knowledge of mathsteps source]** mathsteps' `stepThrough` repeatedly tries an ordered list of simplification functions (e.g., basic simplifications, collect-like-terms, arithmetic, distribute, fractions, division) on the tree, takes the first that changes the expression, records it as a step, and loops until there is no change, with a max step count as a safety net. Each function returns a `Node.Status` with changeType, oldNode, newNode and substeps. Equation solving simplifies each side, then applies "add/subtract/multiply/divide both sides" moves chosen by inspecting where the variable is. Ordering the rule list *is* the pedagogical policy. That is simple but brittle, and it is likely close to how math-blocks works today.
- The Wolfram principle ("don't explain the fast algorithm; run a separate pedagogical rule system") supports keeping math-blocks' step-producing rewriter separate from any fast canonicalizer/CAS used for equivalence checking.

## 4. Proof-assistant approaches to readable steps and LLM + symbolic verification

### Takeaway
Proof assistants separate *search* (e-graphs, ATPs, LLMs, which are untrusted and may be unreadable) from *reconstruction* into a checked, readable chain (Lean `calc`, `simp?` → `simp only [...]`, Sledgehammer → Isar/metis). This is the right pattern for a solver: use any engine to find a path, then replay it through small, named, verified rewrite rules to produce Steps. 2025 LLM work follows the same split: the LLM proposes steps, and SymPy/Z3/a proof checker verifies each step.

### Cited Findings
- lean-egg (Marcus Rossel, TU Dresden) is an equality-saturation tactic built on the Rust `egg` library. It reconstructs a Lean proof from the e-graph, so neither egg nor the tactic must be trusted ("If something goes wrong, Lean will not accept the constructed proof"). Its saturation is "partially unsound", but Lean's LCF kernel keeps overall soundness. The default saturation time limit is about 3 s. — [Rossel MSc thesis 2024](https://cfaed.tu-dresden.de/files/Images/people/chair-cc/theses/2407_Rossel_MA.pdf); [Bridging Syntax and Semantics of Lean Expressions in E-Graphs (arXiv 2405.10188)](https://ar5iv.labs.arxiv.org/html/2405.10188); [Reservoir page](https://reservoir.lean-lang.org/@marcusrossel/egg); [Lean Together 2025 Zulip](https://leanprover-community.github.io/archive/stream/474713-Lean-Together-2025/topic/Marcus.20Rossel.3A.20Egg.3A.20An.20Equality.20Saturation.20Tactic.20in.20Lean.html)
- Explanation extraction is a weak point: handling of e-graph justifications (explanations of rewrites) can lose rewrite steps needed for reconstruction. The Equational Theories Project reported reconstruction issues. Proofs found by egg can be turned into `calc` style with a `calcify` tactic. — [Equational Theories blueprint, e-graphs chapter](https://teorth.github.io/equational_theories/blueprint/egraphs-chapter.html); [Equational Theories Project paper (arXiv 2512.07087)](https://arxiv.org/pdf/2512.07087)
- "Equality Saturation as a Tactic for Proof Assistants" was presented at the EGRAPHS 2022 workshop (PLDI). — [PLDI 2022 EGRAPHS](https://pldi22.sigplan.org/details/egraphs-2022-papers/6/Equality-Saturation-as-a-Tactic-for-Proof-Assistants)
- MATH-VF (2025): a Formalizer translates each LLM reasoning step into formal form, and a Critic checks it with Z3 and SymPy. — [arXiv 2505.20869](https://arxiv.org/html/2505.20869v1)
- Step-level verifier benchmarks: Hard2Verify (Oct 2025) assesses step-level verifiers on frontier math, and ProcessBench targets locating the first erroneous step. A 2026 robustness study of LLM step-level verification exists ("Beyond the Answer Key"); I saw only its abstract listing. — [Hard2Verify (arXiv 2510.13744)](https://arxiv.org/html/2510.13744v1); [arXiv 2608.28725](https://arxiv.org/pdf/2608.28725); also [Selective latent steering for step-wise verification (arXiv 2605.20745)](https://arxiv.org/pdf/2605.20745); [Let's Verify Math Questions Step by Step (arXiv 2505.13903)](https://arxiv.org/html/2505.13903v2)

### Inferences
- **[unverified, prior knowledge]** Lean 4 `simp?` prints a `simp only [lemma1, lemma2, …]` call listing the lemmas actually used. This is a "trace → minimal rule set" pattern that math-blocks can copy: run a broad simplifier, record which rules fired, and present only those. Lean `calc` blocks are chains of `_ = rhs := by justification`, structurally identical to a Step list with a per-step justification. Isabelle Sledgehammer calls external ATPs/SMT solvers, then reconstructs the proof with `metis`/`smt` or as a readable Isar proof. The ATP output itself is not shown.
- Architecture consequence: a fast canonicalizer or e-graph (e.g., egg compiled to WASM, or a TS e-graph) could find *a* path or test equivalence. The user-facing Steps must come from replaying named, small rules. If the e-graph is used, its explanation API (egg's `explain_equivalence`) is the bridge, but it may give unnatural orderings that need pedagogical re-ordering.
- LLM integration pattern for a tutor: LLM proposes the next step or phrases the hint; the symbolic core (a) checks equivalence and (b) recognizes the rule via `diagnose`. Never present an LLM step that the core cannot verify.

- No 2025–2026 paper was found that evaluates an LLM + CAS step verifier *inside a K-12 tutor* with learning outcomes.

## 5. Choosing among multiple valid steps: cost models, pedagogical orderings, configurable levels

### Takeaway
Published systems mostly use **ordering** (rule priority / left-biased choice in a strategy) rather than numeric cost. Ideas' `onefirst` picks from `allfirsts` by rule ordering. mathsteps and Wolfram encode preference in the order of heuristics. Granularity "levels" come from hierarchical labels (Ideas `label`, Andes hint sequences, Wolfram's expandable steps), not from re-solving. Knowledge tracing (BKT) supplies a per-student signal that can decide which labeled sub-strategies to expand or collapse.

### Cited Findings
- `onefirst` "uses the allfirsts service and the rule ordering" to choose a single next step. — [Properties of Exercise Strategies (arXiv 1012.5561)](https://arxiv.org/pdf/1012.5561)
- Wolfram's heuristics deliberately follow "the approach a human would most likely take" rather than the most efficient algorithm. Expert reviewers judge didacticism. — [Wolfram|Alpha Blog 2009](https://blog.wolframalpha.com/2009/12/01/step-by-step-math/)
- Andes' next-step help is a sequence of hints from general (goal) to specific ("bottom-out"). — [VanLehn et al. 2005](https://www.public.asu.edu/~kvanlehn/distrib/AndesLessonsLearnedForWeb.pdf); [Gertner et al., Procedural help in Andes](https://www.cse.unr.edu/~sjose/Papers%20Referenced/Procedural%20help%20in%20Andes%20Generating%20hints%20using%20a%20Bayesian%20network%20student%20model.pdf)
- Knowledge tracing tracks mastery per production rule, which can drive what to show. — [ScienceDirect overview](https://www.sciencedirect.com/topics/computer-science/cognitive-tutor)
- Students commonly skip or combine primitive steps (Andes), so systems need tolerance for coarser student granularity. — [VanLehn et al. 2005](https://www.public.asu.edu/~kvanlehn/distrib/AndesLessonsLearnedForWeb.pdf); [van der Hoek et al. 2025](https://arxiv.org/abs/2507.13651)

### Inferences (concrete TS design)
- Selection policy layers:
  1. **Strategy order** (hard preference). For linear equations: simplify each side → collect variable terms on one side → collect constants on the other → divide by the coefficient. This is a `Seq` of `Label`ed sub-strategies with `PreferLeft` choices inside.
  2. **Tie-break cost** among `allfirsts` candidates: e.g., prefer avoiding fractions, prefer fewer resulting nodes, prefer moving the smaller-coefficient variable term so the coefficient stays positive, prefer outermost/leftmost location. A simple lexicographic cost tuple is easier to explain and test than learned weights.
  3. **Student-relative**: when tracing a student, continue from *their* expression (restart the strategy there) so hints match their path rather than an ideal path.
- Levels and granularity: tag each rule and label with a category (`arithmetic`, `like-terms`, `distribution`, `inverse-op`) and a depth. The step tree is always generated at the finest grain. A presentation filter collapses subtrees by category or by depth, or by student mastery (BKT p(known) > threshold → collapse). This avoids running separate solvers per level and keeps `before`/`after` consistent at every level.
- Hints from the same structure: hint 1 = the label of the next sub-strategy ("Get the x terms on one side"), hint 2 = the rule message ("Subtract 2x from both sides"), hint 3 = bottom-out (the `after` expression). This matches the Andes general-to-specific ladder.
- Mal-rule budget: given van der Bent et al.'s warning that the number of buggy rules explodes, keep a small curated set for high-frequency algebra errors (sign error moving terms across `=`, distributing to the first term only, dividing only one term by the coefficient, adding a term to only one side, combining unlike terms).
